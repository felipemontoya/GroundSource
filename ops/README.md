# ops

Everything needed to deploy, run, observe, and recover the services:
container definitions for deployment, infrastructure configuration, CI/CD
wiring, migration and backup procedures, monitoring, alerts, runbooks.

Local development lives in `../dev/` instead. Where the two need the same
thing (an image, a service definition, an environment contract), share it
rather than maintaining two copies that drift apart.

## What runs where

| Piece | Where | Declared in |
|---|---|---|
| Backend (`api/`) | Render web service, Starter, Virginia | `tofu/api.tf` |
| Database | Render Postgres 17, Basic-256mb, Virginia, private network | `tofu/database.tf` |
| Agreement page (`pages/acuerdo/`) | Cloudflare Pages, built from the repo | `tofu/pages.tf` |
| DNS | Namecheap: two CNAMEs, by hand or by `manage_dns` | `tofu/dns.tf` |
| Infrastructure state | Cloudflare R2 bucket, encrypted by OpenTofu | `tofu/versions.tf` |

Names: the API at `groundsource.projects.felipemontoya.co`, the page at
`acuerdo.felipemontoya.co`. The reasoning behind the choices is in
[ADR-0003](../docs/adrs/0003-hosting-render-and-cloudflare-pages.md).

Expected cost: about USD 7 (web) + USD 6.30 (database) + model calls.
The backend estimates model spend from the tokens it is billed for and
logs a warning at USD 10 a month (soft limit); at USD 30 (hard limit) it
stops generating until the next month and answers with passages only. So
about USD 23 a month at the soft limit, and never more than about USD 43.
Pages, R2 at this size, and DNS cost nothing.

## Secrets

The repository is public. Every secret lives in a git-ignored `.env` file
and nowhere else in the tree:

- `ops/tofu/.env` — credentials for Render, Cloudflare, R2, Namecheap, the
  OpenAI key the backend uses, and the passphrase that encrypts the state.
  Template: `tofu/.env.example`.
- `dev/.env` — the local stack's values. Template: `../dev/.env.example`.

Secrets that reach the platforms go through OpenTofu variables, so they
appear in the state — which is why the state is encrypted before it is
uploaded. `DJANGO_SECRET_KEY` is generated by Render and never leaves it.

## One-time setup, by hand

These steps create accounts or grant access, which no provider can do for
itself. Do them once, in this order.

1. **OpenAI.** Create a project for GroundSource with its own API key.
   Pay with **prepaid credit and auto-recharge off**: that, not a budget
   alert, is the hard stop on spend. Put the key in `TF_VAR_openai_api_key`.
2. **Render.** Create the account and a workspace (Hobby is enough). Connect
   GitHub and grant access to the repository. Create an API key; put it in
   `RENDER_API_KEY`, and the workspace id (`tea-…`) in `RENDER_OWNER_ID`.
   Not the user id (`usr-…`): with that, creating the database fails with a
   bare `not found`. `GET https://api.render.com/v1/owners` lists the right
   one.
3. **Cloudflare.**
   - Install the Cloudflare Pages GitHub app on the repository (Workers &
     Pages → Create → Pages → Connect to Git). A Pages project sourced from
     GitHub cannot be created until the app has access.
   - Create an API token with *Account → Cloudflare Pages: Edit*; put it in
     `CLOUDFLARE_API_TOKEN`, and the account id in
     `TF_VAR_cloudflare_account_id`.
   - Enable R2, create the bucket `groundsource-tofu-state`, and an R2 API
     token with *Object Read & Write* on that bucket only. Its keys go in
     `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`, and
     `https://<account id>.r2.cloudflarestorage.com` in `AWS_ENDPOINT_URL_S3`.
4. **State passphrase.** Generate one (`openssl rand -base64 32`), store it
   in a password manager, and put it in `TF_VAR_state_passphrase`. Without
   it the state cannot be decrypted.
5. **Namecheap (optional).** To let OpenTofu create the DNS records, enable
   API access (Profile → Tools → API Access; Namecheap only grants it to
   accounts that meet its requirements), allowlist this machine's public
   IP, fill the `NAMECHEAP_*` variables and set `TF_VAR_manage_dns=true`.
   Otherwise create the records by hand in step 3 below.

## Deploying

From the repository root, with `ops/tofu/.env` filled in. `make tofu` runs
OpenTofu from its official image; nothing needs installing.

```
make tofu ARGS="init"
make tofu ARGS="plan -out=deploy.tfplan"
make tofu ARGS="apply deploy.tfplan"
```

To deploy the backend before Cloudflare is set up, set
`TF_VAR_enable_pages=false`: the Pages project is left out, and the API
accepts only `https://acuerdo.felipemontoya.co` as an origin until it is
turned back on.

Then:

1. **Wait for the first deploy.** Render builds `api/Dockerfile`, runs
   `migrate` as the pre-deploy step (which also creates the `vector`
   extension), and starts the service. `make tofu ARGS="output api_url"`
   gives its `onrender.com` address; `<api_url>/health` must answer `200`.
2. **DNS.** Unless `manage_dns` is on, create at Namecheap the two records
   listed by `make tofu ARGS="output dns_records"` (Advanced DNS → Add new
   record → CNAME). Render and Cloudflare then verify the names and issue
   certificates on their own; that can take a while after the record
   propagates.
3. **Ingest the agreement** — see below. Until then the page reports that
   the backend does not have its document.

After that, a push to `main` redeploys whatever it touched: `api/**`
redeploys the backend, `pages/acuerdo/**` rebuilds the page. OpenTofu is
only needed again when the infrastructure itself changes.

## Ingesting into production

Ingestion runs from a workstation against the production database; the
PDF never goes to the server. Only the agreement is ingested there —
never a local test-bed document, and the script refuses those by name.

```
make ingest-acuerdo
```

or, for any other document under `sources/`:

```
ops/ingest-production.sh <file> <slug> --language spanish --nickname "..." --title "..." --edition "..."
```

`ops/ingest-production.sh` opens the database to this machine's public IP
(a targeted OpenTofu change, overriding `TF_VAR_db_admin_cidrs`), waits
until the connection is accepted, runs `ingest_source`, `verify_anchors`
and `embed_source` from the local stack's image with `DATABASE_URL` pointed
at production, and closes the database again on exit, even when a step
fails. Keep `TF_VAR_db_admin_cidrs=[]` in `ops/tofu/.env`, so that an
ordinary plan never reopens it. Embeddings use the `OPENAI_API_KEY` in
`dev/.env` and cost cents.

Using the same slug as locally means `pages/acuerdo/src/document.ts`
needs no change.

## Watching the spend

```
cd dev && docker compose run --rm -e RUN_MIGRATIONS=0 -e DATABASE_URL api python manage.py show_usage
```

(with the database opened to this machine and `DATABASE_URL` set to
`make tofu ARGS="output -raw database_external_url"`) prints this month's
estimated spend against the soft and hard limits, and each day's model
calls, refusals, tokens and cost. Crossing either monthly limit also logs a
warning in the service's Render logs.

The estimate prices tokens at `chat_price_*_per_mtok` in
`tofu/variables.tf`: change those together with `chat_model`, or the limits
are enforced against the wrong price. OpenAI's dashboard is the authority
on the real bill; the project's prepaid credit is the last stop.

## Backups

Render keeps point-in-time recovery for paid Postgres instances (up to 7
days). The database holds nothing that cannot be regenerated from the
source PDF and the commands above, at the cost of a re-ingestion and a few
cents of embeddings.

## Known gaps

- On the very first apply, the service's first deploy can reach the
  database before it accepts connections, and the pre-deploy `migrate`
  fails with *Connection refused*. Once the database shows `available`,
  trigger a manual deploy (dashboard, or `POST /v1/services/<id>/deploys`).
  Seen on 2026-09-22.
- The per-client limit counts in one process's memory. It is correct for
  one instance; a second instance needs a shared cache first.
- `docs/planning/adversarial-review.md` §9 lists what should exist before
  the page is announced publicly: a "not an official service / text as
  signed" notice, a rectification channel, and whole-unit answers. None of
  it is infrastructure, and none of it is done yet.
